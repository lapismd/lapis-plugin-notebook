# Notebook Input Package Spec

Canonical rendered spec: [Notebook Input Package](../../../spec/src/20-packages/notebook-inputs/index.md).

## Purpose

`@lapis-notes/notebook-input` owns host-neutral notebook input helpers that can be shared outside the product plugin.

## Current Functionality

- Exposes `transformObservableViewof()` for the supported plain `const|let|var name = view(expression)` source transform.
- Emits `lapis.view(name, node)` calls for transformed input cells, using the canonical Lapis notebook global from `@lapis-notes/notebook-stdlib`.
- Exposes `loadNotebookDomRuntime()` for lazy assembly of the DOM-backed notebook runtime only when a runtime host has already decided DOM-backed execution is required. The package now owns the `Inputs` namespace exposed to notebook cells, mounts supported controls from `@lapis-notes/ui` primitives, throws explicit errors for unsupported factories, and returns tracked `Inputs` wrappers alongside `html` and `svg`.
- Exposes `createTrackedNotebookInputs()`, `attachNotebookInputMetadata()`, and `getNotebookInputMetadata()` so runtime hosts can carry reconstructable input metadata from Observable factories to later output/persistence layers without parsing source text.
- Exposes `canReconstructNotebookInput()` and `reconstructNotebookInputNode()` so runtime hosts can detect rebuildable structured inputs and recreate supported controls directly from persisted metadata generated by the local runtime.
- Exposes `styles.css` as a notebook-input-owned stylesheet entrypoint so notebook hosts can load the current UI-backed control styling without importing upstream CSS directly.
- Exposes `isTemplateStringsArray()` and htl template tag types used by hosts that bridge `lapis.html`/`lapis.svg` output helpers with htl tagged templates.
- Exposes `bindNotebookInputNode()`, `getNotebookInputNodeValue()`, and `setNotebookInputNodeValue()` for host-neutral DOM input value seeding, current value reads, input/change listener binding, and listener disposal.
- Exposes `createNotebookViewRuntime()` for the host-neutral `lapis.view` binding workflow: resolve a promised DOM node, seed and observe the input value, register the live DOM output, forward tracked input metadata into the host output factory, append the typed output, and notify the host about value changes through callbacks.

## Boundary Rules

The package may lazily load DOM-only helper code, the Svelte runtime, and `@lapis-notes/ui` primitives from `loadNotebookDomRuntime()`, but it must not load that surface during product plugin activation or import app/runtime-specific modules at top level. It must not import app APIs, workers, DOM registries, or notebook sessions at top level. Product runtimes remain responsible for deciding when DOM helper packages are needed, providing `lapis.view` host callbacks, allocating DOM output ids, registering DOM output nodes, persisting input values, and emitting rerun requests.
